# ИИ-агент проверки требований

Проект для **BCC-HUB x MNU FinTech Hackathon**. Консольный агент выполняет статическое ревью документа с программными требованиями по ISO/IEC/IEEE 29148:2018 (п. 5.2.5, 5.2.6) и IEEE Std 830-1998 (п. 4.3) и пишет отчёт на русском языке в Markdown.

Агент не тестирует программу. Он проверяет качество документа **до разработки**: выделяет атомарные требования, ищет двусмысленность, непроверяемость, противоречия, пропуски и лишние проектные решения.

## Как работает агент

1. Читает документ: `.pdf`, `.docx` (вместе с таблицами), `.md`, `.txt`.
2. С помощью Gemini выделяет атомарные требования и присваивает им ID `REQ-001`, `REQ-002`, … (исходный номер, например `Ф-1`, сохраняется).
3. Проверяет каждое требование пакетами. Требования, которые модель пропустила, перепроверяются по одному.
4. Проверяет набор целиком: модель получает **полный текст документа** и список требований, поэтому видит таблицы, статусы API, пустые разделы и расхождения между частями документа.
5. Каждая цитата модели сверяется с исходным текстом. Замечание без подтверждённой цитаты отбрасывается. Для каждой цитаты указывается место: страница PDF или строка файла.
6. Отчёт собирает код, поэтому обязательная структура соблюдается всегда.

## Модель

По умолчанию используется `gemini-2.5-flash` через бесплатный Gemini API (Google AI Studio). Платный ключ не нужен. Модель можно сменить в `.env` (`GEMINI_MODEL`) или флагом `--model`.

## Установка

Нужен Python 3.11 или новее.

### Windows PowerShell

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
```

Если PowerShell запрещает активацию окружения, выполните в этом же окне:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

### Linux/macOS

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

## Как получить ключ и куда его положить

1. Откройте [Google AI Studio](https://aistudio.google.com/apikey) и войдите в Google-аккаунт.
2. Нажмите **Create API key** и скопируйте ключ.
3. Откройте файл `.env` в корне проекта и вставьте ключ:

```env
GEMINI_API_KEY=ваш_ключ
GEMINI_MODEL=gemini-2.5-flash
```

`.env` указан в `.gitignore`. Не коммитьте его и не публикуйте ключ.

## Запуск одной командой

```bash
python main.py --input "путь/к/требованиям.pdf" --output output/report.md
```

Отчёт будет записан по пути из `--output` (в примере это `output/report.md`). Папка создаётся автоматически.

Пример на документе из репозитория:

```bash
python main.py -i docs/requirements.md -o output/report.md
```

Другие параметры: `python main.py --help`. Старая форма `python agent.py вход выход` тоже работает.

## Структура отчёта

1. **Паспорт прогона:** документ, дата и время, модель, версия агента (commit или tag из Git).
2. **Таблица нарезки:** ID в отчёте, ID в документе, раздел, место (страница или строка), краткая формулировка.
3. **Проверка каждого требования:** статус, цитата, дефекты с критерием, критичностью, доказательством, риском и рекомендацией.
4. **Проверка набора целиком:** полнота, противоречивость, дублирование, трассируемость, терминология, безопасность и эксплуатация.
5. **Сводка:** число требований и нарушений, распределение по критичности, список критичных дефектов с цитатами.
6. **Вердикт:** GO / CONDITIONAL / NO-GO и приоритет исправлений.

Если запрос к модели не удался, это видно прямо в отчёте: требование получает статус «НЕ ПРОВЕРЕНО», а не «нарушений не обнаружено».

## Версия агента в паспорте

Версия берётся из Git: `git describe` и хеш коммита. Поэтому запускайте агент из клона репозитория. Если папки `.git` нет (например, проект скачан архивом), используется `AGENT_VERSION` из `.env` или файл `VERSION` с пометкой «вне Git-репозитория».

## Лимиты бесплатного Gemini

На бесплатном тарифе действует лимит запросов в минуту. При ответе 429 агент ждёт столько, сколько просит сервер (обычно 30–60 секунд), и повторяет запрос, до 5 попыток. Число попыток задаётся в `GEMINI_MAX_RETRIES`. При неверном ключе или имени модели агент сразу останавливается и выводит причину от API.


## Ограничения

- Сканированные PDF без текстового слоя нужно сначала распознать (OCR). Агент предупредит о страницах без текста.
- Качество смыслового анализа зависит от модели. Агент гарантирует структуру отчёта и подлинность цитат, но не полноту найденных дефектов.
