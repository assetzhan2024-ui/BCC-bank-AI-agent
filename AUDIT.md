# Журнал исправлений

## Исправлено после ревью кода

- **Версия в паспорте.** Раньше `AGENT_VERSION=1.0.0` из `.env.example` перекрывал Git, и в отчёте всегда стояло `1.0.0`. Теперь первым берётся commit/tag из Git.
- **Проверка набора целиком.** Этап 3 получал только выделенные цитаты и не видел таблиц, статусов API и пустых разделов. Теперь модели передаётся полный текст документа, и цитаты сверяются со всем документом.
- **Пропущенные ревью.** Если модель не вернула проверку требования или запрос упал, требование перепроверяется отдельным запросом. Сбой одного запроса больше не обрывает весь прогон.
- **Честный статус.** Требование со статусом «НЕ ПРОВЕРЕНО» больше не помечается как «нарушений не обнаружено». Сбой модели сам по себе не даёт NO-GO, но не даёт и GO.
- **Цитаты везде.** У «Других системных дефектов» и в списке критичных дефектов теперь выводятся цитаты и место в документе.
- **Место в документе.** У каждой цитаты указаны страница PDF или строка файла.
- **Неточные цитаты.** Если цитата модели не найдена, это явно помечается в отчёте.
- **Чтение PDF.** pypdf на PDF с выравниванием по ширине склеивал слова и переставлял их. Основной извлекатель теперь pdfplumber, pypdf остаётся запасным. Добавлен тест на такой PDF.
- **Сверка цитат.** Не зависит от разметки Markdown, вида кавычек и тире, меток страниц и переносов строк в PDF.
- **Лимиты Gemini.** При 429 агент ждёт столько, сколько просит API, а не 1–2 секунды. При неверном ключе останавливается сразу и показывает причину.
- **Репозиторий.** Удалена устаревшая копия `BCC-agent-upload/`. Отчёты из `output/` больше не игнорируются Git, чтобы сгенерированный отчёт можно было приложить к сдаче.

## Исправлено после первого реального прогона

- **Модель.** `gemini-2.5-flash` закрыта для новых ключей (HTTP 404). Модель по умолчанию — `gemini-3.8-flash`.
- **Поминутный лимит больше не считается исчерпанной квотой.** Gemini присылает одинаковый текст для поминутного и дневного лимита; теперь тип квоты определяется по деталям ответа (`PerMinute` / `PerDay`).
- **Экономия запросов.** Все требования проверяются одним пакетом, повтор пропущенных — одним запросом. Прогон стоит 3 запроса вместо 9 и более.
- **Фатальные ошибки останавливают прогон сразу:** неверный ключ, недоступная модель, исчерпанная дневная квота. Лишние запросы не тратятся.
- **Причина ошибки видна.** Вместо «не смог выделить ни одного требования» выводится ответ API.
- **Пути.** Относительные пути `--input`/`--output` работают и из папки проекта, и из текущей папки терминала.
- **`tzdata`** добавлен в зависимости (часовой пояс в паспорте на Windows).
- **Тест защищает `.env.example`:** в нём не должно быть ключа.

## Ограничения

- Сканированные PDF требуют предварительного OCR.
- Полнота найденных дефектов зависит от модели.
- Перед сдачей нужно выполнить реальный прогон на документе организаторов и закоммитить созданный отчёт.
